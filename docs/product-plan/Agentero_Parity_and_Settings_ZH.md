P0 解决第一次使用和每天阅读的流程。P1 工作为一篇论文从入库走到写作。P2 纳入扩展、远程与跨平台能力。每行都是功能对齐范围。

## 2. 给前端的第一批任务

保持当前左聊右读和侧边浮动工具。设置继续从左侧「模型与服务」进入。建议按以下顺序拆成独立任务，前后端可并行。

| 任务 | 页面和交互 | 接口与验收 |
| --- | --- | --- |
| FE-01 模型与服务 | 默认显示「模型连接」「论文来源」「PDF 处理」「任务上限」四组。首屏只显示当前模型、状态和连接操作。端点、协议、模型 ID、预算放入展开区。 | 真实桌面已有 `services.get`。保存接 `services.save`，测试接 `services.test`，凭据走 `services.credentials`。后三项当前是契约和模拟能力，由后端接通。上游连接失败时，用户仍可导入、阅读、批注。 |
| FE-02 统一导入 | 首页、主题和资料库打开同一个导入流程。支持选或拖 PDF，粘贴 DOI/arXiv。每条有匹配预览、目标主题和进度。 | PDF 复用 `library.import_pdf/list/catalog`。标识符查找及 Zotero 需要新接口。验收三条并行样例，重复 PDF 只关联，书目缺附件仍可保存，失败可逐项重试。 |
| FE-03 阅读查找与续读 | 浮动工具加页内查找入口和章节导航，可用快捷键调出。保持阅读位置。找图结果用缩略图、页码和对象类型呈现。 | 现有 `reader.pdf`、`visual.search`、`visual.objects` 可用。页级保存要扩展现有段落位置契约。关应用并重开后回到论文和页码，从第二页查中英文关键词可跳转、下一项和返回。 |
| FE-04 引用与证据 | 当前论文打开「参考文献」时，面板可搜、看出处、打开已入库条目、把外部条目加入候选。论点下可展开每篇论文的贡献和原文。 | 复用 `literature.refs`、`evidence.open`、`synthesis.list/wiki`。文献补全和 PDF 引用内链匹配需联调。验收 ALCE → ASQA 打开引用语境，证据卡跳准确版本与页码，缺证据及条件不同有各自状态。 |

### FE-01 的细节

- **读取状态**。连接卡显示「未配置／已保存待测试／测试中／可用／失败」。用户保存配置时保留正在编辑的字段。点击测试只验证已保存的配置，测试负载用固定短问题。认证失败、限额、网络超时、模型不可用、运行时缺失分别提示可采取的动作。
- **首次配置**。DeepSeek 首先提供当前正式适配器。凭据写入由桌面宿主处理，页面只回读是否已设置、可选脱敏预览和测试状态。替换或移除在宿主确认。配置与凭据分开落盘，日志、备份、普通 RPC 与浏览器存储只包含无密钥数据。
- **配置变更**。保存用 `base_revision` 防覆盖，发生冲突保留草稿并提供重新读取。任务启动使用确认时的模型、端点、预算和材料快照。确认后改了模型或端点，要重新确认。正在跑的任务沿用原快照。
- **能力来自后端**。DeepSeek 之外的自定义提供商、Ollama 视觉、OpenAlex 和可选 PDF 解析器，按服务能力展示字段、测试和启停。模型设置由 PaperTrace 后端负责。对不能保存的真实能力显示具体缺项，同时可以用浏览器样例开发状态。
- **开发入口**。改造现有设置页和契约，运行模式下验收。设置页读得到固定的 DeepSeek、预算占位，真实 worker 尚未实现保存、测试和密钥对话框。DSH 的提供商行、凭据只写和版本冲突可作行为参考。

## 3. DSH 瘦身与新增后端

当前 PaperTrace 每次任务启动固定版本的 DSH `sdk-minimal`，使用临时目录和启动补丁。补丁已禁用终端、默认文件工具、通用 MCP 和若干产品组件，并设置只读策略。研究任务对模型提供四个受范围限制的工具，查论文引用、搜全文、读片段、查主题 Wiki。论文、批注、任务状态和证据由 PaperTrace 的 SQLite 保存。

已有三次本机模拟对照的冷启动中位数为 285→291 毫秒，峰值内存采样中位数为约 133→153 MiB。这一轮配置对照没有测出资源下降。缩减依赖还需要看实际装包、构建和运行，尤其核对极简包声明里仍出现的终端、文件、任务和日志依赖。

1. **保留引擎**。留模型适配、Agent 循环、工具调度、权限、流式事件、取消、错误回传和运行所需的最小会话组件。记录已加载插件和对模型公布的工具。
2. **裁发行包**。从独立的 PaperTrace 启动组合排除 DSH 的 Web/桌面壳、市场、终端、SSH、通用工作区和通用托管设置。在锁文件、运行依赖、构建与事件路径都验证后，才考虑从派生源码分批删除。外接 ACP 与 MCP 走独立适配器，可选配置，不拖进默认 DSH 运行组合。
3. **先接公开文献发现**。通过 OpenAlex 做主题候选、DOI 对齐和书目引用线索。外部引用记录供导航，支持程度由本地 PDF 核查。缓存书目请求结果，检索服务不可用时继续读已入库论文。 [OpenAlex Works 与引用](https://help.openalex.org/data/works/citations/)
4. **用可选解析器改善证据**。保留 PDF.js、现有快速提取、OCR/复杂版面按需处理。已有 GROBID 可做书目线索，新增实验先对照 MinerU 或 RAG-Anything 的解析能力。将有效结果统一写为论文版本、页码、区域与来源，继续使用现有 SQLite/FTS5 和 Wiki。只有漏检实验显示需要时，再加入语义重排或向量索引，并比较增加的安装体积和时间。 [SQLite FTS5](https://www.sqlite.org/fts5.html) · [MinerU](https://opendatalab.github.io/MinerU/) · [HKUDS RAG-Anything](https://github.com/HKUDS/RAG-Anything) · [ACP](https://agentclientprotocol.com/get-started/introduction)
5. **验收后才替换默认组合**。同一批公开 PDF、同一固定测试服务，跑真实工具调用、流式输出、取消、异常重试、重启读回、越出已选范围时拒绝、图文证据定位。比较安装体积、运行依赖数、冷启动、峰值内存和首次增量耗时。功能有回归或资源收益不足时，原运行组合继续作为回退路径。

## 4. 怎样证明 PaperTrace 做得更好

完整体验用同一组公开论文跑一次，从批量导入、找依据、对照论文、保存论点到核查稿件，记录完成时间与中断点。基础操作以任务成功率、点击次数和错误后是否找得到下一步来评估。

| 要验证的能力 | 用户看见的结果 | 对照验收 |
| --- | --- | --- |
| 看懂论文之间的关系 | 区分「引用了」「使用了基准」「结果可直接比较」「只支持这句话的一部分」，标出依据与实验条件 | 用 ALCE/ASQA 验证基准使用，RARR/Self-RAG 验证方法比较。人工核查关系、实验条件和过度归因。 |
| 写作时找到可靠的引用 | 一句话拆到可核查的论点，每篇论文各自对应贡献、适用条件、原文页及区域 | 用同一模型、论文和检索预算比较固定检索、Agent 补查、带已审阅 Wiki 的 Agent。记录正确证据覆盖和误判为充分支持的比例。 |
| 研究积累可以继续用 | 新会话找回已审阅观点，仍能点回论文。来源换版后能指出受影响的观点并提示复核 | 保存一条观点，重启复用，更换一个版本后核对受影响项。记录回查用时、重定位正确率和无关条目是否受到影响。 |
| 用模糊描述找图 | 中文或英文描述能找回实际图块，用户点结果跳回原页 | 在人工标注的图、表、公式和易混淆样例中比较首位命中率、前五命中率、区域定位与缺证时的反馈。 |

功能对齐可从官方说明逐项核对。比较结果需要同任务实测，当前文档中的优先级和组件取舍属于拟议开发安排。
