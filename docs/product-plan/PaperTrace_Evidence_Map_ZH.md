# PaperTrace 主题证据图

作者把六篇论文放进「长回答怎样做到有据可查？」主题。打开证据图，她先看到自己关心的三个方面：长回答要覆盖什么，模型在什么时候查证，怎样评价引用是否充分。点开任一论点，右侧显示每篇论文贡献了哪一部分，并能翻到对应的 PDF 页。她想写「检索能保证长回答正确」时，图上保留这个待查问题，并提示她需要什么实验。

[打开交互原型](PaperTrace_Evidence_Map.html)。原型使用本轮人工核对的公开论文样例，可以点节点、切换引用视图、反查论点和打开 PDF。下面的编辑论点、局部重查和版本联动是开发方案。

## 1. 先画论点，再看论文

默认用两列显示「作者的论点 → 贡献论文」。作者可以编辑论点，把一个太大的问题拆成几句可核查的主张。主题较大时，只显示当前论点附近的论文，其他部分用搜索和展开进入。点击一篇论文能反查它参与了哪些论点。同一论文在引用方和被引用方各有显示身份；引用视图按有向论文对归组，下面保留具体出现位置。点选节点后，从右侧列表选择某一条贡献或引注，在论文阅读器中打开对应原文，同时查看条件和待查问题。手机上用同序的节点与证据列表，保留键盘操作和可见焦点。

| 要区分的问题 | 图上怎么表达 | 成立需要什么 |
| --- | --- | --- |
| B 为什么引用 A？ | 独立的「查论文引用」视图。方向从引用方指向被引用方。 | B 的正文引用位置和书目条目，经过标识匹配。用途可包括介绍背景、沿用方法、使用数据或基准。同一论文对可有多个引用位置和多种用途。 |
| 论文对论点贡献了什么？ | 默认视图。边记录论文的具体贡献，例如「定义问题」「提供方法」「给出实测结果」「限定条件」。 | 附上该论文自己提供的证据。另记它对具体子论述的支持程度，可为充分、部分、冲突或待查。 |
| 两份结果能放在一起比较吗？ | 在证据详情里对齐任务、数据、划分、指标、设置。 | 对比方法流程与对比实验结果分别判定。只有条件对齐才谈同口径优劣。因果归因另外要求针对该改动的实验证据。 |
| 表面上有好几篇支持，实际来自哪一份结果？ | 详情展开「追到原研究」，同一结果的转述合并展示。计数单位是独立实验或原始结果。 | 依据正文引用和具体实验追溯。无法确认共同来源时保留未知，独立来源数也保持未定。同用一个数据集不自动合并不同实验。 |

分类借鉴 CiTO 的引用用途与 MultiCite 的多标签、多句上下文。论述核查借鉴 SciFact 的证据判定和 FActScore 的拆分方法。PaperTrace 另存「论文原文说了什么」「模型怎样判断」「用户有没有采纳」，也区分证据观点、原研究和引用出现位置。 [CiTO](https://www.sparontologies.net/ontologies/cito) · [MultiCite](https://aclanthology.org/2022.naacl-main.137/) · [SciFact](https://aclanthology.org/2020.emnlp-main.609/) · [FActScore](https://aclanthology.org/2023.emnlp-main.741/)

例如，「ALCE 在带引用的长回答评估中使用 ASQA」的两条边承担不同工作。ALCE 的第 3 页写明评估用到 ASQA，ASQA 的第 1 页说明任务为什么需要覆盖不同解释。对于「长回答要覆盖不同解释」这个论点，ASQA 提供任务定义，ALCE 的采用记录提供背景，独立依据仍来自 ASQA。写方法综述时，可以并列 RARR 的生成后查证与 Self-RAG 的生成过程中按需检索。图上标注这是流程对照，两篇论文的结果仍要对齐设定才能比较。 [ALCE §3.1](https://aclanthology.org/2023.emnlp-main.398.pdf#page=3) · [ASQA 摘要](https://aclanthology.org/2022.emnlp-main.566.pdf#page=1) · [RARR 摘要](https://aclanthology.org/2023.acl-long.910.pdf#page=1) · [Self-RAG 摘要](https://arxiv.org/pdf/2310.11511v1#page=1)

## 2. 解析一次，检索时按需补材料

现有后端已经能导入 PDF、按页索引、读取版面对象和引用上下文，并校验锚点里的原句。第一步沿用这套快速导入。先给每页记录可用范围，例如正文、图注、表格单元格、公式或仅页面图像。阅读顺序错乱、扫描文本缺失、表头断裂等问题独立排队处理。对这些页做增量解析，避免一次导入阻塞整个主题。

存储上保留原始 PDF 和版本哈希。每项证据指向版本、页码、对象和坐标，跨页证据允许多段区域。解析重跑写新的解析修订和锚点候选。旧锚点继续打开旧区域，重新定位成功也保留历史。“PDF 第 4 页”始终指文件页序，同时可单独展示印刷页码。表格证据需要保留行列标题和单位，图像证据保留图注、图块和正文引述。用户问「两条曲线后段分开的那张图」，先查图注和正文的图号描述，需要看曲线时，再读取候选图块。

| 开源参考 | 采用方式 | 接入前要证明 |
| --- | --- | --- |

## 3. RAG 补证据，Wiki 保存审过的关系

**第一次查一个论点。** Agent 拆分论述并分配阅读预算。精确的 DOI、论文别名、数据集名和引文标记走书目与词项查询。全文检索按小问题找候选段落，再展开邻段、原始图表和引文。如果候选只覆盖方法，Agent 继续定位实验与局限。如果引文只是在转述，应追到原研究。发现相反结果时，先对齐条件。预算用完仍保留可用结论、未查材料和停止原因。

**下次打开同一主题。** 按论点命中已审阅的 Wiki 记录，取得版本和证据位置。即时结果来自用户已采纳且当前有效的记录。草稿、待复核项可展示为线索。复用条件读论述修订、来源版本与分析规则：只改标题或展示顺序可复用；编辑句子时先确认是同义改写还是新断言，默认将新句列为待核。增加范围或遇到反例时，重查受影响的部分。新论文只与存在链接、共享实体或与问题检索匹配的候选建立待审关系。用户也可以点选任意论文对补查。候选筛选属于提速手段，图上不会把漏查的关系显示为不存在。

**来源换版。** 用反向依赖把旧锚点映射到受影响的论点、Wiki 边和引用句子。界面保留旧原文，将这些边标为待复核，其余结果可以继续用。若新旧版本的片段不同，先展示差异，由用户采纳新版归因。同一 PDF 重新解析只更新解析修订，并核对旧锚点的定位有效性。PDF 字节变动才产生来源新版本。采纳时在同一事务校验 Wiki 修订号和纸库的当前版本；如先发生换版，过期提交提示刷新后复核。重试和重建索引以 PDF 哈希、解析修订及任务范围为依据，避免生成重复记录。

实现先投影现有 `synthesis.list` 和 `synthesis.wiki`。论文通过来源版本 ID 对应到库，论点用稳定 ID，贡献边用论点、子论述与来源版本建立关联，证据点击复用 `evidence.open`。正文引注沿用 `literature.refs`。正式版需要为子论述分配跨修订的稳定身份，并在持久化层维护按证据和来源版本查询的反向依赖。单条边同时记录判断状态与审阅状态。当前接口的 `verified` 表示结构和出处满足校验，应在界面呈现为「有原文依据」，人工采纳用单独的状态。 [现有综合契约](../contracts/literature-synthesis.md) · [技术书第 6–10 节](../source/PaperTrace_Technical_Book_ZH.md)

### 让对话里的发现进入证据知识库

论文导入后自动生成资料卡。研究对话为 Wiki 补充有原文依据的发现，例如某篇论文沿用了另一个基准、两种方法只在流程上可比、或某段结果只支持用户论点的一部分。同一主题里的不同会话可以沿用这些发现。

每轮对话结束时，Agent 在后台检查新获得的证据是否值得保存。新关系、有实质变化的适用条件、反例和能够继续调查的问题可以生成候选。复述已有发现时复用原条目；同一个论点获得新证据时建议更新，给出变化；与既有记录发生冲突时保留双方依据。普通问答和缺来源的推测留在会话。缺证据但作者关心的内容可以存成待查问题。

每个候选保留论点或问题、论文贡献、适用条件、证据锚点和来源会话。可追溯的书目引用来自导入索引，语义判断先作为草稿。默认把草稿集中放到主题右侧的证据区域，用户可以保存、稍后看或忽略。用户明确说「把这条存进 Wiki」时，Agent 提交他选中的发现；相关范围不清楚时先展示候选。已采纳的条目才能作为长期研究记录复用，后续引用时仍可回原文。

主题右侧默认展示当前对话关联的几条证据，点开可切换到完整证据图。图从作者的问题或论点展开，显示各篇论文的贡献、限制与待查项。选中节点后，在同一面板里直接预览证据，也可以回到产生发现的会话。待采纳草稿可独立展开，待复核的旧结论保留标记。

证据预览按原文类型展示。段落显示原句和可展开的前后文，图和子图显示原图块与图注，表格保留列标题和单位，公式保留原版渲染与编号。每项都显示论文名、版本和页码。点「回到原文」在右侧阅读器打开该页，并在定位准确时高亮区域。只能定位到整页时，直接打开该页。Agent 的图像描述和判断放在原文旁，可用于搜索和解释。

例如用户问「ALCE 用了 ASQA，所以能否说 ASQA 评估了引用质量？」Agent 查阅两篇，提出一条可保存的发现：ASQA 定义了歧义问题的长回答任务；ALCE 采用 ASQA，并在自己的框架里评估引用质量。右侧显示 ASQA 对任务定义的贡献、ALCE 对评估方法的贡献，以及 ALCE → ASQA 的采用关系。用户追问「两个指标到底怎么计算？」时，Agent 补读 ALCE 第 4 页，建议更新已有记录。 [ASQA 摘要](https://aclanthology.org/2022.emnlp-main.566.pdf#page=1) · [ALCE 数据选择](https://aclanthology.org/2023.emnlp-main.398.pdf#page=3) · [ALCE 引用质量](https://aclanthology.org/2023.emnlp-main.398.pdf#page=4)

## 4. 开发与验收顺序

| 顺序 | 前后端产物 | 验收条件 |
| --- | --- | --- |
| 1. 关系图落到现有数据 | 在主题综合页增加证据图入口。先渲染一个选定提纲或 Wiki 修订，前端沿用证据侧栏。 | 用六篇样例能按论点和论文反查。ALCE → ASQA 显示为引用用途。RARR 与 Self-RAG 在流程维度可并列，界面保留效果比较前提。 |
| 2. 增量解析和混合检索 | 给解析结果加页级能力与质量记录，复杂页走可选解析器。以现有全文检索作基线，按问题融合书目线索、正文片段、对象描述和已审阅 Wiki。 | 双栏、扫描页、跨页表、模糊找图分别统计原文定位与检索命中。失败后保留可读 PDF 和已完成索引。 |
| 3. 研究积累可以复用 | 为论述和关系维护版本及反向依赖。连通证据图、Wiki 和引用建议。 | 加入一篇仅转述同一结果的论文，图中仍只计一份独立来源。替换其中一篇的 PDF 后，重开主题能定位哪些边和稿件句子要重查，并打开旧版证据。 |

**硬性验收** 检查所有可点击边的版本和页码，拒绝跨主题与不存在的锚点。检查正文引用缺失、表格单位缺失、引用回环、同一结果被多篇综述转述、实验设置不一致，以及采纳与换版并发。缺材料要能完成其余部分并留下待查的问题。

**效果对照** 沿用现有六篇论文与评估管线，另外留出主题和测试问题做盲评。先比较现有 FTS 和增加语义／版面对象时的证据 Recall@k、定位误差和索引成本。再在同模型、同论文和同证据阅读预算下比较「固定检索」「Agent 补查」「Agent 补查并用 Wiki」，记录支持强度误判、同源误计、改版后找到受影响结论的比例、冷启动／重复任务耗时、模型调用和 token。用户走查记录从打开论点到核对来源的动作数。把解析、判断和界面指标分别报告，以便定位改进来自哪一层。 [课程指南](../COMP7608B_LLM_Project_Guideline.pdf) · [现有评估脚本](../../backend/evaluate_synthesis.py)
