# PaperTrace 前端交接 · DeepSeek 模型设置

2026-11-21

用户可以在桌面端的「模型与服务」里查看 DeepSeek、修改模型 ID、保存并测试连接。设置保存在当前工作区，重开应用后会读回。更换模型后，已开始的研究任务继续用原来的模型。准备过但还没开始的任务需要重新确认。

## 现有页面怎么接

| 页面上的操作 | 后端能力 | 前端需要做什么 |
| --- | --- | --- |
| 加载模型设置 | `services.get({})` 返回当前模型、固定端点和凭据状态。 | 沿用现有加载流程。用 `credential_configured` 显示是否已提供凭据，连接是否成功以测试结果为准。 |
| 修改并保存模型 | `services.save` 接收原表单，接受模型 ID 变更。 | 沿用现有输入框和保存按钮。将端点设为只读。遇到 `STALE_REVISION` 时提示重新加载设置。 |
| 测试已保存的连接 | `services.test` 返回 `ok` 和 `message`。DSH 只发送一句固定测试提示。 | 沿用先保存、再测试的交互。结果展示在按钮旁。测试失败时保留已保存配置，方便修改后重试。 |
| 管理 API 密钥 | 目前由桌面启动环境提供。宿主钥匙串窗口需要单独接入。 | 桌面模式先隐藏「管理系统凭据」按钮，去掉钥匙串说明。 |
| 编辑预算、检索源和解析器 | 设置接口保留字段，暂时沿用后端运行限制。 | 收起相关编辑控件。保存时仍原样提交后端返回的预算、开关和服务数组。 |

直接复用 [SettingsForm](../../frontend/src/views/ServicesPage.tsx) 和 [接口类型](../../frontend/src/api/services.ts)。`model_id` 和 `models[0].id` 是提供者的固定标识，模型名写进 `models[0].model`。保存请求带 `base_revision`，用当前读到的 `revision`，`operation_id` 仍由现有写入层生成。连接测试的 `id` 使用提供者标识。

目前测试结果通过 `message` 返回简短英文。若需要把认证、限流等提示译成中文，前后端可增加稳定的状态码，保留现有 `ok` 和 `message` 字段。固定端点为 `https://api.deepseek.com/anthropic`。完整请求说明见[服务接口契约](../contracts/services-workspace.md#桌面端当前接入)。

## 联调验收

1. 按[本地宿主说明](../../backend/README.md#启用真实-deepseek-harness-问答)启动桌面端。打开「模型与服务」，确认模型名、端点及凭据状态都能显示。
2. 输入宿主账号能调用的模型 ID，保存并重开应用。确认仍显示所保存的模型。点击「测试连接」，检查按钮附近是否显示结果。
3. 退出应用。在未提供凭据的环境重新启动，运行测试并确认页面仍可编辑模型，失败信息可见。再用两个先后发出的保存请求检查旧版本提示。
4. 启动一个新的阅读或综合任务，确认它使用刚保存的模型。若先打开任务确认、此后改了模型，旧确认应提示重新确认。

本轮验证了现有前端的桌面请求适配器连到 Python worker 的读、存、重读、测试失败及版本冲突。固定版本的 DSH 也已通过本地模拟服务实测，运行测试和综合任务时均采用保存的模型。正式桌面界面点击、生产 DeepSeek 账号及 Windows 运行留在桌面联调验收。
