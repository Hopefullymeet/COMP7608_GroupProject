# PaperTrace MVP Design

更新：2026-10-06。状态：设计草案，尚无实现或实验结果。

## 1. 目标与主流程

帮助用户从 idea 出发，筛选文献、讨论写作思路，并在写作完成后标注和核查引用。用户负责选文献与完成写作，Agent 负责检索和基于原文的辅助。

**idea / 授权读取已有写作 → 搜索候选 → 用户选择入库 → 写作对话与论文关系分析 → 引用标注 → 独立引用回查。**

| 步骤 | 最小行为与输出 |
|---|---|
| 输入 | 接收 idea，或读取用户授权的写作片段，提取研究问题与检索关键词。 |
| 搜索 | 接入一个可用的文献搜索 API，呈现候选列表：题名、作者、年份、链接、相关性理由与摘要。 |
| 入库 | 仅将用户认可的候选加入文献库；支持用户自行添加论文与 PDF。无全文的条目只用于发现文献，不用于全文证据判断。 |
| 写作辅助 | 用户与 Agent 对话收集思路；按授权读取写作、工作区及库内文献，回答问题、寻找证据或比较论文，附原文位置。 |
| 引用标注 | 写作完成后，按授权在库内为需要引用的论述寻找支持证据，生成带引用标记的副本与“论述—文献—原文位置”清单；找不到证据则标为待补充。 |
| 引用回查 | 用户单独发起；回到被引论文，对照论述与原文检查准确性、适用条件和夸大。检查通过则直接返回判定及证据；发现问题则由 LLM 提出修改建议。 |

授权按任务限定到所选写作内容、工作区文件和文献，可在本次任务内复用；调用远端模型时说明将发送哪些内容。原始写作与 PDF 保留，建议由用户采纳。

## 2. 核心设计

### 文献搜索：相关、可靠、覆盖需求

候选 API 为 Consensus 或可提供 Google Scholar 检索结果的服务；实施前验证访问权限与效果，首版只接一个可用接口，不预设其全文能力。

Agent 根据研究问题生成查询；结果无关或遗漏关键子问题时调整查询，再呈现去重后的列表。筛选理由关注研究匹配程度、方法与实验依据、发表来源及局限，不能仅以引用数或排名判断“高含金量”。充分性指是否覆盖用户的关键子问题，并明确仍缺什么证据，不承诺搜尽全部文献。摘要仅用于初筛，用户确认后才入库。

### PDF 入库：统一数据基座

**用户提供 PDF → 提取文本并转 Markdown → 保留页码与章节映射 → 分块 → 建立检索索引与 Wiki 卡片。**

保留原 PDF、书目信息及稳定的论文 / 片段标识，让后续回答与引用可回到原文。首版支持可提取文本的 PDF；扫描件及无法可靠提取的图表、公式标记为需人工处理，不据此生成精确结论。替换 PDF 后重建对应索引与卡片。

### RAG + 轻量 Wiki + 学术 Skill

- **RAG**：检索库内原文片段，读取必要上下文后生成回答，是证据基础。
- **Wiki**：每篇论文一张简短卡片，记录主题、方法、主要结论及库内论文关系，均链接到原文片段。检索时用卡片与关系补充 RAG 的证据入口；Wiki 摘要本身不作为证据。
- **Skill**：一份学术反馈规则，要求区分原文结论与模型推断、保留适用条件、检查实验可比性、证据不足时明确说明。它约束反馈，不替代原文或核验。

Wiki 仅覆盖已入库论文，不构建完整知识图谱。对比基础 RAG 与 RAG + Wiki 的证据召回和构建 / 更新成本，再判断增加的维护成本是否值得。

### 论文关系：限定对象、方向与证据

首版只分析用户指定的库内论文，关系记录包含论文对、类型、方向和原文依据：

| 关系 | 判定依据与输出 |
|---|---|
| 明确引用：B 引用 A | B 的参考文献与正文引用上下文；说明引用用于背景、方法或实验对比。 |
| 方法继承 / 修改：B 基于 A | 明确引用及两篇方法原文；列出保留了什么、修改了什么。仅有引用不能证明方法继承。 |
| 实验对比：B 与 A 比较 | 原文中的对比结果及数据集、指标、基线和设置；条件可比时才描述具体提升，否则说明比较限制。 |

“主题相似”只作为 Wiki 的主题链接，不推定引用或继承关系。不能证明某项修改带来了提升时，区分“作者报告的整体提升”与“该修改的作用尚未验证”；无法确认的关系保留为待核实。

### 引用标注与回查：两个独立任务

**标注**解决“这段论述由哪篇论文的哪段证据支持”：在库内定位证据，保留论述位置、引用映射和原文片段，不强行补引用。

**回查**解决“已有引用是否准确、是否夸大”：只在对应被引论文中补查上下文，再交给类似 Jev 的判断模型 / 评审调用。结果分为支持、部分支持、冲突、证据不足或无法核验，并附依据；缺少全文不得判为通过。问题结果交给 LLM 生成修改建议，通过结果直接返回。Jev 的具体模型、接口和评审规则在实现前确认。

例如，原文仅证明某数据集上的改善，正文却写成“普遍有效”，应指出夸大并建议补上适用范围。自动评审的效果仍需人工标注验证。
